## 고정 인터페이스

새 파일 `js/core/learning-auth.js`에서 다음 비동기 API를 제공한다. Node 테스트에 필요한 생성 함수도 내보낸다. Firebase 접근은 주입 가능한 어댑터로 분리하여 테스트에서만 가짜 인증·명부를 사용한다.

```javascript
await learningAuth.signIn({ classId: '2-1', studentNum: 1, entryCode: '개인코드' });
// 성공: { uid, classId: '2-1', studentNum: 1 }
await learningAuth.getCurrentStudent(); // 검증된 위 객체 또는 미로그인 시 null
await learningAuth.signOut();
```

- 현재 지원 범위는 기존 학급과 같은 `2-1`~`2-11`, 번호 1~27이다. 번호는 정수 또는 숫자 문자열을 받아 정수로 정규화한다. 공백·소수·범위 밖 입력은 거부한다.
- 내부 로그인 주소는 `s-${classId}-${studentNum}@students.donghyun-hackthon.invalid`로 고정한다. 예: `s-2-1-1@students.donghyun-hackthon.invalid`. 실제 학생 이메일을 수집하지 않는다. 후속 계정 발급도 이 규칙을 사용한다.
- 개인 코드는 비밀번호로 Firebase `signInWithEmailAndPassword`에 전달한다. 빈 코드만 사전 거부하고, 대소문자 변경·앞뒤 공백 제거 등을 임의로 하지 않는다.
- 명부 계약은 **`learning_students/{인증 UID}` → `{ classId, studentNum, enabled: true }`**이다. 이번에는 읽기만 구현하며 명부를 자동 생성하거나 수정하지 않는다.
- 인증 후 해당 UID의 문서를 서버에서 읽는다(`get({source: 'server'})`). 문서 존재·활성 상태·학급·번호·인증 계정의 내부 주소 일치가 확인되어야 성공이다. 반환 UID는 Firebase 인증에서만 가져온다.
- `getCurrentStudent()`도 인증 초기 복원을 기다리고 서버 명부를 확인한다. 네트워크 실패를 미로그인 또는 성공으로 바꾸지 않는다. 등록되지 않거나 비활성인 계정은 로그인 상태로 제공하지 않는다.

## 기존 기능을 보존하는 연결 방식

학생 학습 기록 전용 Firebase 앱 이름을 `learning-records`로 사용한다. **설정은 기존 `window.FIREBASE_CONFIG`를 그대로 사용**하며 별도 프로젝트를 만들지 않는다. 앱·Auth·Firestore는 최초 호출 시 한 번 초기화하고 이후 재사용한다.

- 로그인과 명부 조회 모두 이 앱 인스턴스를 사용한다. 기본 앱의 교사 Google 로그인과 기존 익명 평가 계정을 바꾸거나 로그아웃시키지 않는다.
- 전용 Auth는 로그인·복원 처리 전에 `firebase.auth.Auth.Persistence.SESSION`을 설정한다. Firestore 오프라인 영구 저장은 켜지 않는다.
- 사용자·토큰·코드·명부를 직접 localStorage에 쓰지 않는다. 코드·내부 주소를 로그·오류 메시지·URL에 넣지 않는다. 코드 원문은 인증 호출에 필요한 동안만 사용하고 서비스 필드에 보관하지 않는다.
- `signIn`/`signOut`은 기존 `isAssessmentLocked()` 또는 `assessmentWorkspace.active`가 참이면 **인증 상태를 변경하기 전에** 거부한다. 동시에 들어온 인증 변경 요청은 `busy` 오류로 거부하고 첫 요청만 처리한다.
- 새 로그인 시도에서 입력과 잠금을 확인한 뒤 전용 앱의 이전 학생 세션을 종료한다. 인증 실패나 명부 검증 실패 때 이전 학생을 로그인 성공으로 반환하지 않는다. 명부 검증 실패 후에는 전용 앱의 인증도 정리한다. 정리 실패를 숨기지 않는다.
- 미등록 계정과 잘못된 코드는 같은 안내로 처리한다: `학급·번호·입장코드를 확인해 주세요.` 네트워크 장애·요청 과다·인증 설정 미완료는 재시도 또는 교사 확인이 필요한 오류로 구분한다. 클라이언트 지연을 서버 호출 제한이라고 표현하지 않는다.
- 운영 코드에서 가짜 계정이나 공통 코드를 허용하지 않는다. 테스트 어댑터는 테스트 파일에만 둔다.

## 변경 범위와 완료 조건

변경 파일은 새 서비스, `tests/learning-auth.test.cjs`, PRD 9.6의 짧은 진행 기록, `docs/GEMINI_TASK_02_2_RESULT.md`로 제한한다. **이번에는 index.html에 연결하지 않는다.** 다음 화면 연결 단계에서 사용 종료 버튼이 두 인증 세션을 모두 지우도록 함께 처리해야 한다.

관련 Node 검사만 작성·실행한다:

1. 올바른 코드와 일치하는 명부만 성공. 잘못된 코드·명부 없음·비활성·학급/번호 불일치는 거부.
2. 명부 조회 장애가 성공으로 둔갑하지 않음. 잘못된 재로그인 후 이전 학생 객체를 반환하지 않음.
3. SESSION 설정 후 인증, 전용 앱 재사용, 기본 교사/평가 Auth 변경 없음, 새 서비스 생성 뒤 세션 복원도 명부 검사.
4. 평가 잠금 시 인증 변경 없음, 중복 로그인 요청 거부, 로그아웃 뒤 자기 정보 null.

`node tools/check.cjs`도 실행한다. 로컬 브라우저에서는 스크립트를 별도로 로드해 전역 충돌·콘솔 오류·호출 전 Firebase 초기화 부작용이 없는지만 확인한다. 관련 없는 전체 UI 검사는 반복하지 않는다.

결과 문서에는 API·검사 결과·실제 Firebase 미검증 여부를 짧게 쓴다. 운영 인증 공급자 활성화, 실제 학생 계정 생성, Firestore 규칙 변경·배포, 커밋·푸시·병합·배포는 실행하지 않는다. **현재 운영 규칙에 새 명부 접근 허용이 없으면 실제 로그인 흐름은 아직 사용할 수 없다.** 모의 검사 통과를 운영 로그인 완료라고 보고하지 않는다.

후속 연결 항목: 서버 권한을 갖춘 계정 발급과 명부 등록, 자기 명부 읽기 규칙, 로그인 화면, 사용 종료 시 두 인증 세션 정리. 계정 발급용 임시 Auth를 사용할 경우에는 학생 로그인용 SESSION과 달리 메모리 지속성을 적용한다.
