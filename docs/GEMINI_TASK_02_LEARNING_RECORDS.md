## 이번 목표

학생이 문제 추상화 단원의 퀴즈와 실습 내용을 제출하고, 교사가 학급별로 확인하며, 학생이 자기 기록을 다시 보는 흐름을 구현한다. Codex가 먼저 반영한 `정보 놀이터` 이름·홈 안내를 보존한다. 실제 학생의 Google 계정 사용은 어렵다. 학생 화면은 **학급·번호·개인 입장코드**로 진입한다.

`AGENTS.md`, `INTENT.md`, `PRD.md`를 읽고 특히 PRD 9.2·9.3·9.5·9.6을 따른다. Git 상태를 확인해 현재 미커밋 변경을 보존한다. 기존 수행평가의 시간·점수·답안·인증 흐름은 변경하지 않는다. `AGENTS.md`, `백업용/`, 기존 서비스 설정은 수정하지 않는다.

## 학생 확인과 계정 준비

* 개인 입장코드를 실제 Firebase 인증에 연결한다. 이름·번호 일치나 브라우저에 저장한 문자열 비교만으로 로그인 성공 처리하지 않는다. 학생에게 다른 학생의 코드·기록을 내려주지 않는다.
* 최소 기술안은 Firebase Email/Password 인증이다. 학급·번호에 대응하는 내부 로그인 식별자를 사용하되 학생의 실제 이메일 주소를 수집하거나 이메일 인증을 요구하지 않는다. 내부 식별자는 UI·기록에 불필요하게 노출하지 않는다. 이 내부 식별자 연결은 본 프로젝트의 설계안이며 Firebase의 별도 '학급 코드 로그인' 기능이 아니다.
* 교사가 먼저 계정과 학급·번호 관계를 등록하고 개인 코드를 발급한다. 학생이 임의로 번호를 선점해 기록 소유자가 되거나 자기 교사 역할을 만들 수 없어야 한다. 별도 학생 자기 가입 화면은 만들지 않는다.
* 코드는 `crypto.getRandomValues` 등으로 생성하며 단순한 공통 코드·번호·생일을 사용하지 않는다. 원문은 발급 시 교사에게 전달하는 범위로 제한하고 Firestore 문서·로그·Git·URL·localStorage에 보관하지 않는다. 비밀번호 검증·저장은 Firebase Auth에 맡긴다.
* 학생 계정 준비 과정에서 교사의 기존 로그인이 학생 계정으로 바뀌지 않게 한다. 별도 Firebase Auth 인스턴스를 사용할 경우 메모리 지속성을 적용하고 작업 후 해제한다. 계정 생성 성공과 명부 등록 성공을 구분하고, 중간 실패 시 발급 완료로 표시하지 않는다. 이미 존재하는 계정을 덮어쓰거나 자동 삭제하지 않는다.
* 학생 로그인은 세션 지속성을 사용한다. 인증 성공 뒤 서버에 등록된 UID·학급·번호의 관계도 확인한다. 다른 학생으로 전환할 때 앞 학생의 화면·초안·구독을 정리하고 기존 `finishSharedSession`의 종료 원칙을 유지한다. 진행 중 수행평가에서는 계정 전환을 차단한다.
* 잘못된 코드·비활성 계정·네트워크 실패를 정상 로그인으로 처리하지 않는다. 반복 로그인 오류에 재시도 안내를 제공하며 서버 인증의 제한을 클라이언트 지연만으로 대체하지 않는다. 코드 분실은 교사에게 요청하도록 안내한다. 재발급 기능은 서버 권한·기존 세션 처리까지 검증할 수 있을 때만 완료로 표시한다.

Firebase 공식 참고(2026-09-13 확인): [비밀번호 인증](https://firebase.google.com/docs/auth/web/password-auth), [인증 지속성](https://firebase.google.com/docs/auth/web/auth-state-persistence). 운영 프로젝트의 Email/Password 공급자 활성 여부는 별도 확인 대상이다. 비밀 관리자 키를 새로 만들거나 배포 환경 변수를 임의로 추가하지 않는다.

## 제출할 내용

대표 대상은 `unit1` / `abstraction`이다. 기존 학습 내용을 새로 만들거나 차시를 임의로 두 개로 나누지 않는다. 대표 수업 활동 묶음에 안정적인 ID·제목·버전을 부여하고, 이후 실제 차시에 연결할 수 있게 한다.

| 구분 | 제출 시점의 원본 |
|---|---|
| 퀴즈 | 현행 4문항의 문항 ID·선택 답안·문항 버전. 응답 수와 정답 수는 해당 버전의 기준으로 다시 계산 |
| 추상화 실습 | 학생이 정리한 현재 상태·목표 상태·조건·남긴 정보·버린 정보 |
| 공통 | 인증된 소유자·학급·번호, 활동 ID·버전, 서버가 확인한 제출 시각 |

`js/labs/lab-quiz.js`의 `UNIT_QUIZ_DATA`, `userQuizAnswers`, `renderUnitQuiz`, `handleQuizAnswer`와 `js/labs/lab-abstraction.js`의 입력 필드·`registeredConditions`·`currentPoolTags`·`currentTrashTags`를 확인한다. `currentGeneratedPlans`는 AI 생성 또는 대체 제안이므로 학생이 직접 작성한 실천 계획으로 기록하지 않는다. 이번에는 AI 대화·제안 전체를 수집하지 않는다.

## 학생과 교사 화면

1. 일반 수업의 학습 진입은 유지한다. 기록을 제출하거나 조회할 때 학생 로그인을 연결하고, 로그인 때문에 현재 퀴즈·실습 초안이 사라지지 않게 한다.
2. 문제 추상화의 퀴즈·실습에서 찾을 수 있는 `수업에 제출` 동작으로 현재 활동 묶음을 저장한다. 오류 답안·부분 작성도 제출할 수 있다. 정답률·AI 사용 여부·실습 완성을 제출 조건이나 과정점수 감점으로 연결하지 않는다.
3. 서버 확인 전에는 `제출 중`, 실패 시에는 실패 안내와 재시도를 표시한다. 재시도는 같은 제출 요청 ID를 사용해 중복 문서를 만들지 않는다. 새로 제출한 결과는 이전 제출을 덮어쓰지 않고 새 제출 시점으로 구분한다. 매 클릭·매 입력마다 서버에 저장하지 않는다.
4. `나의 기록`은 로그인한 학생 자신의 제출 목록과 원본 상세를 표시한다. 최신 제출부터 확인하고 이전 제출도 구분한다. 제출·불러오기 실패·아직 제출하지 않음을 구분한다. 다른 PC에서 같은 개인 코드로 로그인했을 때 같은 자료가 보여야 한다.
5. 교사용에 `학습 기록` 경로를 추가하고 학급별 학생·최근 제출 시각·퀴즈 응답 수/전체 문항 수·정답 수·실습 제출 상태를 표로 표시한다. 행을 열면 퀴즈 답안과 학생이 작성한 실습 원본을 확인한다. 누락은 점수 0과 구분하고 기록이 없는데 가짜 통계를 채우지 않는다.

## 저장·권한 경계

학생 계정의 소속과 제출물은 기존 수행평가의 `classrooms/{classId}/students/{studentNum}` 자료와 분리한다. 새 평가 준비·종료·재시험이 학습 기록을 삭제하거나 바꾸지 않아야 한다. 새 경로·필드·목록 조회 방식은 PRD 9.6에 실제 구현대로 기록한다.

학생의 UID만으로 자기 명부를 읽고, 그 명부에 연결된 학급·번호의 제출물만 작성·조회할 수 있게 한다. 학생이 보내는 소유자·학급·번호를 신뢰하지 않는다. 다른 학생의 단건 조회·목록·수정·명부 위조를 Firestore 규칙에서 거부한다. 등록된 교사만 학급 기록을 조회한다. 제출물 필드·형식·문자열 크기·지원 버전을 제한하고 화면에는 학생 입력을 안전하게 표시한다. 클라이언트가 주장한 `isCorrect`·총점을 신뢰하지 않는다.

자동 삭제·보관 기간·공식 성적 합산은 임의로 추가하지 않는다. 운영 데이터 보관 기준은 운영 반영 전 확정할 미결정 사항으로 남긴다. 입장코드 발급·회수와 다른 PC 복귀의 실제 운영 절차도 결과 문서에 명시한다.

## 구현 순서와 최소 검증

인증·기록 저장을 작은 서비스 모듈로 분리하고 기존 화면에 연결한다. 프런트엔드는 HTML/CSS/Vanilla JS를 유지한다. 점수 5·25·35 계산, 다른 두 단원의 저장, 전체 디자인 개편을 묶지 않는다.

이번에는 로컬 모의/에뮬레이터 환경의 구현·검증까지 진행한다. 운영 계정 생성, 인증 공급자 변경, Firestore 규칙 배포, 원격 푸시·병합·Vercel 배포는 실행하지 않고 필요한 반영 항목을 정리한다. 로컬 모의 기능은 localhost의 명시적인 시연 모드로 제한한다.

다음 흐름을 실제로 확인한다. 관련 검사를 통과한 뒤 같은 검사를 이유 없이 반복하지 않는다.

* 교사 발급 → 학생 로그인 → 오답·부분 실습 제출 → 교사 조회 → 학생 자기 기록 조회.
* 새 브라우저 문맥에서 같은 계정 로그인 시 기록 복귀, 다른 학생 계정에서는 접근 거부.
* 잘못된 코드, 계정/명부 등록 중간 실패, 중복 클릭, 저장 실패·재시도, 새로고침 초안 유지.
* 실제 Firestore 규칙 검사에서 무인증·다른 학생·명부 위조·교사 권한 없음의 거부. 모의 저장소 검사만 통과했다면 규칙 검증 완료로 쓰지 않는다.
* 기존 평가 중 이동·로그아웃 제한과 새 평가 준비 후 학습 기록 보존.
* 1440·768·390px의 학생 제출·기록 상세·교사 표, 콘솔 오류 확인.

완료 시 `docs/GEMINI_TASK_02_RESULT.md`와 PRD에 변경 파일, 구현한 인증·저장 구조, 실행한 검사, 스크린샷, 운영 반영 전 미결정/미확인 항목을 간결히 기록한다. 실제 Firebase에서 검증하지 못한 부분을 정상이라고 단정하지 않는다.
