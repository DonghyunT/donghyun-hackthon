# 실제 게스트 로그인 — 운영 활성화 완료

2026-09-13 · 작업 브랜치 `codex/real-guest-login`

사용자가 샘플 전용 화면 대신 실제 학생·교사 기능을 사용하는 게스트 로그인을 요청했다. 최초에는 브랜치에 보관했고, 이후 활성화·실제 로그인/저장 검증·병합·배포 제안에 **go!**로 승인했다. 아래 활성화 순서에 따라 해커톤 프로젝트에 반영했다. 원본 서비스와 기존 308명 학생 계정·자료는 변경하지 않았다.

## 구현

- 로그인 창 위쪽의 학생/교사 게스트 버튼 → 서버가 발급한 Firebase custom token → 기존 실제 클래스룸. 별도 샘플 화면과 가짜 제출 상태는 제거한다.
- 발표용 학급 `2-12`, 게스트 학생 1번 `hackathon-guest-student`, 게스트 교사 `hackathon-guest-teacher` 두 고정 UID를 사용한다. UID·학급·교사 권한을 요청자가 임의로 지정할 수 없다.
- 학생은 기존 퀴즈·실습 기록 저장, 자신의 기록 조회, 평가 입장·작성·제출을 사용한다. 교사는 발표용 학생 기록 확인, 평가 준비·시작·종료, 답안 검토·채점·CSV를 기존 화면에서 사용한다. 학생에게는 기존 정책대로 평가 제출 여부를 표시한다.
- 게스트 교사의 실제 1~11반 명부·기록·평가·보관 답안 접근을 Firestore 규칙과 평가 AI API에서 차단한다. 발표반만 개별 조회하며 학생 계정 발급 UI는 제공하지 않는다. 기존 교사의 권한은 유지한다.
- 기존 로그인 사용자를 덮어쓰지 않으며, 평가 진행·중복 로그인 잠금과 SESSION 지속성을 유지한다. 계정 전환은 로그아웃·사용 종료 후 한다.
- 게스트 계정의 제출물은 다른 게스트 사용자와 공유된다. 로그인 안내에 개인정보를 입력하지 않도록 표시한다. 학생·교사를 동시에 시연하려면 별도 브라우저 세션을 사용한다.
- 게스트 로그인 비밀번호나 서명 비밀 키를 브라우저에 배포하지 않는다. 전용 서비스 계정 키는 서버 환경 변수에만 둔다. 로그인 API는 기본 비활성이고 설정 누락 시 503으로 실패한다. IP별 분당 20회 제한은 서버 인스턴스 단위이며 전체 플랫폼 한도가 아니다.

## 현재 검증과 한계

- Node 자동 검사 56개 통과: 기존 기능, 게스트 학생·교사의 SDK 인증 연결, 기존 계정 보존, 잘못된 명부·권한 거부, 실패 시 로그아웃, 토큰 서명·고정 신원·만료, 요청 변조·과다 요청 차단, 서버 평가 권한 검사.
- JavaScript 문법·HTML 자산 참조 검사 통과.
- Firebase 공식 `projects:test` 컴파일 오류 0개 확인 후 해커톤에 규칙을 배포했다. `--apply`로 전용 2개 계정·학급·역할·서명 키를 준비하고 Vercel 서버 설정을 등록했다.
- 실제 Firebase 검사 33개 통과: 게스트 신원·발표반 읽기, 실제 반 접근 차단, 자기 역할 변경 거부, 3개 단원 퀴즈 기록 저장과 학생·교사 조회. 근거: `scratch/guest-live-access.json`. 검증용 퀴즈 3개는 발표 계정에만 남겼다.
- 운영 내장 브라우저에서 학생·교사 게스트 버튼으로 SDK 로그인, 학생 기록 3개 조회, 교사 발표반 1개 목록과 계정 발급 숨김, 학생 평가 대기실, 교사 평가 시작, 객관식 응답과 자유 설계 현재/목표 입력, 최종 제출 성공 및 교사 제출 1명 수신을 확인했다. 검증 회차를 마감하고 새 평가 준비로 원본을 보관했다.
- 운영 로그인 API HTTP 200, 실제 배포 READY 확인. 최초 운영 병합 커밋 `592ee2c2762ca10146bcb2db675e72c21c89f1b2`, 배포 `dpl_2kBTfFYnV81XdGhhr5NdDEeE4MBs`. 이 문서의 후속 동기화 커밋은 코드 변경이 없다.
- 검증 중 Firestore 일시적 unavailable 경고가 있었으나 재시도 후 실제 서버 저장과 수신이 완료됐다. 다중 사용자의 동시 게스트 편집·대규모 부하·Google 팝업은 이번 검증 범위가 아니다. 게스트 검토는 기존 채점 UI를 연결하며 실제 성적 확정은 하지 않았다.

## 적용한 활성화 절차

1. 이 브랜치의 규칙을 해커톤 Firebase에 배포하고 접근 경계를 확인한다. 이전 규칙에서 공개 교사 역할부터 활성화하지 않는다.
2. `FIREBASE_TOOLS_LIB`를 기존 Firebase CLI lib 경로로 지정하고 `node tools/provision-guest-accounts.cjs --apply`를 실행한다. 도구는 운영 규칙이 로컬 규칙과 같은지 확인한 뒤 발표 전용 2개 계정과 학급·명부·대기 회차·교사 역할만 생성한다. 기존 자료는 덮어쓰지 않는다.
3. 도구가 만든 `scratch/private-access/guest/service-account.json`은 Git/배포 제외 폴더에만 보관한다. 전용 서명 계정에는 프로젝트 IAM 역할을 추가하지 않는다. Vercel 해커톤 프로젝트의 서버 전용 `FIREBASE_GUEST_SERVICE_ACCOUNT`에 JSON을, `GUEST_LOGIN_ENABLED`에 `true`를 설정한다. 원본 서비스에는 설정하지 않는다.
4. 승인된 환경에서 실제 학생 로그인 → 3개 활동 기록 저장/조회, 교사 로그인 → 발표반 조회 → 평가 준비/시작 → 학생 제출 → 교사 검토를 확인한다. 게스트로 실제 반 명부·평가 조회/조작을 요청하면 거부되는지 반드시 확인한다. 실패하면 공개 활성화를 진행하지 않는다.
5. 확인된 변경을 해커톤 운영 브랜치 `feature/hackathon`에 병합하고 배포 READY 및 연결 주소를 확인한다. 배포 확인 후에만 실사용 완료로 보고한다.

끄려면 새 로그인 발급을 `GUEST_LOGIN_ENABLED=false`로 중단한다. 이미 로그인한 세션까지 중단하려면 두 게스트 Auth 계정과 발표 명부/교사 역할을 비활성화한다. 5분은 custom token 교환 유효기간이며 로그인 세션이 5분 뒤 종료된다는 뜻이 아니다. 게스트 자료의 일괄 삭제나 자동 초기화는 이번 변경에 포함하지 않는다.

설계 참고: [Firebase custom token 공식 명세](https://firebase.google.com/docs/auth/admin/create-custom-tokens), [관리자 계정 생성 API](https://docs.cloud.google.com/identity-platform/docs/reference/rest/v1/accounts/signUp), [서비스 계정 키 생성 API](https://docs.cloud.google.com/iam/docs/reference/rest/v1/projects.serviceAccounts.keys/create). 2026-09-13 확인.
