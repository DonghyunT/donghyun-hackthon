## 이미 구현·배포된 내용

- 학생용 이름은 **정보 놀이터**. 차분한 UI와 넓은 픽셀아트 캠퍼스가 첫 화면이다.
- 5개 교육과정 영역을 건물로 표시한다. 로봇은 하단 정문에서 출발하며 방향키로 이동한다. 건물 클릭 또는 가까이에서 Enter로 수업 페이지에 바로 들어간다. 모달 입장은 대체되었다.
- 전체 영역의 소개·주제는 있으나 실제 퀴즈·실습은 문제 추상화, 알고리즘 설계, 순서도 연구소 3개이다. 나머지 영역의 활동까지 구현되었다고 말하지 않는다.
- 3개 활동의 퀴즈·실습 기록 저장과 학생 자신의 기록 조회, 교사의 학급별 기록·수행평가 관리를 연결했다.
- 실제 학생 308명: 2학년 1~11반, 각 1~28번. 학급·번호와 학생별 6자리 숫자/소문자 비밀번호를 사용한다. UID는 학생이 입력하는 로그인 값이 아니다.
- 교사는 Google 로그인 및 별도 비상계정을 사용한다. 학생에게 수행평가 결과는 제출 여부만 표시하는 정책이다.
- 학생/교사 게스트 버튼은 실제 Firebase 로그인·저장·평가 기능에 연결된다. 예전 샘플 전용 체험 화면은 대체되었다.
- 게스트 학급은 발표용 **2-12**. 게스트 교사는 실제 1~11반에 접근할 수 없다. 공개 게스트 사용자들은 같은 게스트 기록을 공유한다.
- 학생 명부는 learning_classes/{classId}/students/{NN} 하위 구조다. 이전 평면 명부 308개는 사용자 승인으로 정리했다. 로그인 계정은 유지한다.
- 공유 PC를 고려해 SESSION 인증과 sessionStorage를 사용한다. 학생 자료를 localStorage에 저장하지 않는다.

상세: [게스트 로그인](GUEST_LOGIN_BRANCH.md), [학생 로그인·평가](HACKATHON_LOGIN_RELEASE.md), [활동 기록](ALL_UNIT_RECORDS_RELEASE.md), PRD 9.7~9.13.

## 교육·제품 합의

- 과정중심평가를 위한 정량 기록으로 교사의 맥락 있는 판단을 돕는다. 학생의 추가 작성 부담과 교사의 채점 부담을 줄인다.
- 수행평가 3회 만점은 30·30·40점, 각각 제출 기반 과정점수 5점을 배정하는 기획이다. 구체적 인정·환산 기준과 자동 계산은 미확정이다(PRD 9.3).
- 위 학기 배점과 기존 한 번의 순서도 평가 내부 30·30·40 배점을 혼동하지 않는다.
- 일반 실습의 AI 도움과 수행평가 도움 범위를 구분한다. 임의의 감점·성찰 과제를 추가하지 않는다.
- 서비스 전체의 부드러운 클릭·전환은 낮은 우선순위 후속 작업: [UX 후속 작업](UX_BACKLOG.md).
- 학생에게 친근한 화면과 명확한 조작을 우선한다. 사용자에게 정중하고 간결하게 설명한다.

## 최근 검증과 한계

2026-09-13 게스트 로그인 변경 기준이다. 미래 변경에도 통과한다고 가정하지 않는다.

- Node 검사 56개, JavaScript 문법·HTML 자산 참조 검사 통과.
- Firebase 규칙 컴파일 오류 0, 실제 접근·기록 저장 검사 33개 통과.
- 운영에서 학생·교사 버튼 로그인, 기록 조회, 발표반 조회, 평가 시작 → 학생 작성·제출 → 교사 제출 수신을 확인했다.
- 검증 평가 답안은 보관하고 새 회차를 대기 상태로 준비했다. 검증용 퀴즈 기록 3개는 발표 계정에 남았다. 이후 조작으로 바뀔 수 있으므로 현재 DB 상태는 필요할 때 재확인한다.
- 배포 READY 확인. Firestore 일시적 unavailable 경고가 있었고 재시도로 저장되었다.
- 대규모 동시 접속, 동시 게스트 편집, Google 팝업, 실제 성적 확정은 이번 검증 범위가 아니다.
- 브라우저 캡처는 필요한 시각·실제 연동 확인에 최소한으로 사용한다. 코드로 확인 가능한 부분은 코드 검토와 관련 검사로 확인한다.

## PC·AI 교대 방법

- 코드·공유 문서는 Git으로 옮긴다. 이전 PC에서 브랜치·커밋·미커밋 변경·원격 푸시 여부를 남긴다. 새 PC에서 무작정 덮어쓰거나 강제 초기화하지 않는다.
- 한 작업 브랜치에 두 PC/AI가 동시에 쓰지 않는다. 인수인계 후 기존 쪽은 편집을 멈춘다. 독립 작업은 별도 브랜치를 사용한다.
- schoolbooks/ 교과서 PDF와 scratch/private-access/ 비밀 자료는 Git 제외다. 교과서는 로컬 개발 참고용이며 외부 업로드·배포하지 않는다.
- .env*, js/data/config.js, .vercel, 개인 CLI 인증은 Git으로 이동하지 않는다. 새 PC에서 필요한 인증·설정을 확인한다. 비밀번호·서비스 계정 JSON을 대화나 문서에 붙이지 않는다.
- 게스트 서버 설정 이름은 GUEST_LOGIN_ENABLED, FIREBASE_GUEST_SERVICE_ACCOUNT이다. 값은 공유 문서에 넣지 않으며 절차는 GUEST_LOGIN_BRANCH.md를 따른다.

## 매 작업 종료 시 갱신할 내용

이 문서의 오래된 현재 상태를 교체한다. 상세 기능은 PRD와 해당 작업 문서에 기록한다.

1. 현재 목표, 새로 결정한 사항, 아직 답이 필요한 질문.
2. 브랜치·코드 커밋, 미커밋/미추적 파일, 원격 푸시 여부.
3. 구현한 내용과 다음 한 가지 작업.
4. 수행한 검증, 대상 버전·환경, 실패·미검증 항목.
5. 병합·배포 상태와 해당 변경의 승인 여부.

문서 자체 커밋 해시는 자기 본문에 재기록하지 않아도 된다. 종료 메시지에 브랜치와 커밋을 알린다. 구현 의도를 검증 완료로 표현하지 않는다.
