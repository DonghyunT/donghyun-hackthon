## 이번 대화의 사용자 요청

- 정보 수업에서 사용할 웹앱을 장기적으로 여러 단원을 지원하는 플랫폼으로 확장한다.
- 학생이 클래스에 들어와 배우고 기록을 남기며 수행평가를 치를 수 있게 한다.
- 임시 서비스명은 교수평기 올인원이다.
- 과정중심평가를 위해 일반 수업의 차시별 퀴즈·실습 결과와 시간 제한 수행평가 결과를 기록한다. 정량 자료로 교사의 맥락 있는 판단을 돕고 채점 부담을 줄이는 방향이다. 세부 기록 후보는 PRD 9.2, 과정점수 기획 기준은 9.3을 따른다. 활동 인정·점수 환산·과정 로그의 세부 수집 범위는 아직 미정이다.
- 사용자의 현재 평가계획은 수행평가 3회(각 30·30·40점)이다. 제출 기반 과정점수 5점씩과 수행평가 25·25·35점을 기획 기준으로 채택했다. 이는 기존 순서도 평가 내부 30·30·40점과 다른 구분이며, 구체적 인정·환산 기준은 PRD 9.3에서 미확정으로 관리한다.
- 최초 논의 당시 작업 시간은 약 4~5시간으로 설명했으며 현재 남은 시간은 확인하지 않았다. 기존 코드 사용은 자유롭다.
- 이 내용을 바탕으로 전체 페이지 구조부터 빌드를 시작한다. Codex가 PRD와 지시서를 작성하고 Gemini가 앱 구현을 맡는다. 1차 범위는 PRD 9.4와 아래 구현 지시서를 따른다.
- 위 작업 폴더에서 개발을 진행한다.

## 제안한 첫 버전 범위 (미구현)

기존 알고리즘 실습과 평가 기능을 재사용한다. 플랫폼 홈과 단원 목록, 클래스 입장, 대표 활동 하나의 저장·복원, 교사의 결과물·평가·피드백 조회를 연결한다. 시간이 남으면 두 번째 단원의 짧은 활동으로 확장 가능성을 확인한다.

핵심 시연: 클래스 입장 → 활동 → 저장·이어하기 → 제출 → 교사 검토·피드백 → 학생 기록 확인.

## 현재 준비 상태

- 기존 코드를 가져온 뒤 해커톤 전용 저장소로 origin을 변경했다.
- AGENTS.md, INTENT.md, PRD.md, docs/HANDOFF.md를 확인했다.
- Gemini가 `codex/platform-structure`에서 1차 화면을 구현했다. Codex가 화면 중첩·작은 창의 복귀 버튼·탐색 상태를 보완했다. 최신 검증·병합·배포 상태는 [1차 구조 검토서](PLATFORM_STRUCTURE_REVIEW.md)를 따른다. 기록 저장과 과정점수 계산은 후속 작업이다.
- Production 브랜치는 `feature/hackathon`이며 2026-09-13 사용자가 이번 구현의 점검·병합·배포를 승인했다. 새 저장소만 대상으로 삼는다.
- 새 도메인의 홈 화면 접속과 새 Firebase 프로젝트·DB 존재를 확인했다. 후속 사용자 요청으로 Vercel의 Production·Preview·Development에 `FIREBASE_PROJECT_ID=donghyun-hackthon`을 등록하고 Production 재배포 Ready를 확인했다. 관리 도구 대상도 새 프로젝트로 로컬 수정했다. 실제 로그인·권한·저장·AI 검증은 별도이다.
- 기존 문서의 배포 승인·완료 기록은 과거 작업의 기록이다. 이번 해커톤의 배포 승인이나 검증 결과로 해석하지 않는다.

## 다음 작업

1. 서버 대상 환경 변수는 운영 반영되었고 Firebase 관리 도구 수정은 아직 로컬 변경이다. 기존 미커밋 문서 변경을 보존하며 새 인증·권한·저장 연결을 확인한다. 기존 서비스·DB는 변경하지 않는다.
2. 대표 단원의 차시·활동, 학생 식별과 기록 보관 범위를 정한 뒤 학생 제출 → 교사 조회 → 나의 기록을 연결한다.
3. 과정점수 인정·누락·예외·환산 기준을 확정한 뒤 평가 점수에 연결한다. 이번 배포 승인을 후속 변경의 상시 배포 승인으로 확대하지 않는다.

기존 환경은 HTML/CSS/Vanilla JS, Vercel API, Firebase이다. 기존 클래스룸은 평가 회차 중심이며 지속적인 학생 계정·학습 기록 연결 설계가 필요하다. 로컬 시연 진입점은 docs/HANDOFF.md를 따른다.
