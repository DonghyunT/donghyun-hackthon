# 정보 놀이터 — 로그인·학습 기록·수행평가 배포

2026-09-13. 사용자가 Codex의 직접 구현·커밋·병합·배포를 요청했다. 이어 학생 308명과 교사 비상계정의 개별 비밀번호 생성, Google 교사 권한과 로그인 설정·접근 규칙 반영을 명시적으로 승인했다.

## 실제 사용 흐름

- 학생: 홈 → 학생 로그인 → 학급·번호·배부받은 비밀번호 → 퀴즈·실습 → 수업에 제출 → 나의 기록. 문제 추상화 원본을 제출 시점마다 보존하며 부분 작성·오답도 받는다.
- 교사: Google 로그인(등록 계정 `adh103006@gmail.com`) 또는 교사 비상 로그인 → 학급 선택 → 학생·학습 기록. 학생을 열면 제출 원본과 퀴즈 응답/정답 수를 확인한다.
- 평가: 교사가 학급의 새 평가 준비 → 로그인한 학생이 대기실 입장 → 교사 동시 시작 → 학생 객관식·단답형·순서도 작성/제출 → 교사 확인·채점·CSV. 기존 시간·문항·채점 정책을 유지하며 28번까지 지원한다. 평가 중 계정 전환을 차단한다.
- 공용 PC: 작업을 마치면 로그아웃 · 사용 종료. 학생 인증은 SESSION이며 브라우저 종료가 서버 기록 삭제를 뜻하지 않는다.

## 계정과 데이터

학생 2학년 1~11반 × 1~28번 = 308개 계정을 새 Firebase에 준비했다. 실제 학생 이름·이메일은 수집하지 않고 기본 이름은 `번호번 학생`이다. 학생마다 무작위 개별 비밀번호를 생성했다. 공통 비밀번호는 사용하지 않는다.

계정 파일은 `scratch/private-access/README.txt`에서 안내한다. `classes/2-1/student-accounts.txt`처럼 반별 배부표를 두고, 같은 학급의 `students/01.txt`~`28.txt`에는 학생 한 명의 전달용 메모만 둔다. 각 학급의 관리용 JSON도 그 학급 폴더 안에 둔다. 비상 교사는 `teacher/emergency-login.txt`로 분리했다. 학생에게는 본인의 메모만 전달한다. Git의 scratch 무시 규칙과 Vercel 제외 규칙을 확인했다. 웹앱·Firestore·로그에는 비밀번호를 보관하지 않는다.

최종 구현은 기본 Firebase SESSION 인증을 수업·평가에 함께 사용하여 동일 UID를 유지한다. 이전 2-2A의 학생 전용 앱 설계는 채택하지 않았다. 추가 계정 발급 시에만 별도 메모리 Auth를 사용하여 교사 세션을 보존한다. 기존 로그인 계정을 바꾸려면 사용 종료 후 다시 입장한다.

사용자의 관리 동선 피드백을 반영하여 최종 명부는 **`learning_classes/{반}/students/{두 자리 번호}`**로 구성한다. 예: `learning_classes/2-1/students/01`. 각 학생 아래 `submissions/{uuid}`에 제출 원본·서버 시각을 보관한다. Firebase 인증 UID는 학생 문서의 필드로 연결하며 폴더 이름으로 사용하지 않는다. 교사는 학급 안의 28명만 조회하고 학생은 서버 UID가 일치하는 자기 문서만 읽는다. 다른 학생 조회·명부 수정·교사 권한 위조는 거부한다. 기존 계정 UID와 비밀번호를 모두 유지한 채 학급 11개·학생 308개의 이전을 대조했다. 이전 평면 명부는 사본 검증 후 정리하며 로컬 마이그레이션 백업은 공개·배포하지 않는다.

Firebase `donghyun-hackthon`의 비밀번호/익명 공급자 활성화, 새 Vercel 도메인 허용, 두 교사 권한 등록, Firestore 규칙 컴파일·배포를 완료했다. 익명 인증은 일반 실습의 기존 AI 호출용이며 학생 로그인이나 평가 응시 권한을 주지 않는다. 기존 `donghyun-algo`·기존 GitHub·Vercel 서비스는 변경하지 않았다.

## 검증

- Node 관련 검사 31개(인증·원본 수집·재시도·평가/API/회차), 로컬 평가 UI 10개를 확인했다. 평가 화면의 일반 도움 차단·새로고침·제출 실패/재시도·교사 검토·시간 종료를 포함한다.
- 실제 해커톤 Firebase에 연결한 로컬 Edge에서 비상 교사 로그인, 학생 28번의 잘못된 비밀번호 거부/정상 로그인, 수업 제출·교사 조회, 다른 학생 조회/명부 목록/교사 역할 위조 거부, 실제 평가 준비·시작·제출·교사 수신, 새 브라우저에서 기록 복귀, SESSION 및 로그아웃을 확인했다.
- 1440·768·390px의 학생/교사 화면 가로 넘침을 검사했다. UI 신규 작성 후 불필요한 기록 화면 중앙 여백을 정리했다.
- 근거: `scratch/release-qa/assessment-ui.json`, `scratch/release-qa/live-login.json`, 학생 화면 PNG. 학급별 구조 전환 뒤 실제 서버 검사 9항목과 Node 31개를 다시 통과했다. 실제 검사에서 만든 제출물과 비어 있던 학급의 검사 회차 3개 문서를 검사 후 제거했다. 학생 계정은 유지한다.
- Google 공급자 활성화·도메인·역할은 확인했지만 실제 Google 팝업 사용자 로그인을 완료한 것은 아니다. CLI의 Google 액세스 토큰을 대체 사용한 검사는 audience 불일치로 실패하여 성공 근거에서 제외했다. 교사 비상 로그인은 실제 검증됐다.

## 남은 범위

비밀번호 분실 재발급 UI, 학생 비밀번호 변경 UI, 보관·삭제 운영 정책, 다른 두 단원의 일반 수업 기록, 학기 과정점수 자동 환산은 후속 작업이다. 비상 교사 계정은 Google 계정과 같은 교사 권한이므로 비밀번호를 교사만 보관한다. 308명 전체 동시 접속 부하 시험은 하지 않았다. 기존 평가의 AI 채점 API는 단위 검사했으며 이번 배포에서 유료 AI 실호출은 하지 않았다.
