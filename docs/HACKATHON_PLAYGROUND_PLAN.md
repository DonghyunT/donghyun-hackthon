# 정보 놀이터: 움직이며 들어가는 수업 지도

> 설계·자산 제작 과정의 기록입니다. 후속 변경으로 대체된 초안도 포함합니다. 현재 동작은 PRD 9.12~9.13과 [지도 검증 기록](PLAYGROUND_RELEASE.md), [게스트 로그인](GUEST_LOGIN_BRANCH.md)을 따르며 이 계획을 처음부터 다시 실행하지 않습니다.

작성: 2026-09-13 · 상태: 구현 완료, 독립 검토 및 배포 준비

## 승인된 최종 배치와 범위

2026-09-13 사용자가 ZEP처럼 친숙한 공간 탐색, 단원별 특색 있는 다섯 건물, 대칭 배치, 40분 내 범위 조정과 빌드·병합·배포를 승인했다. 독립 서브에이전트가 계획 대비 구현을 검토한다. 교육과정 20·조작 25·접근성 15·시각 15·호환성 15·비공개/배포 준비 10점의 기준으로 평가하며, 95점 초과와 발표 차단 결함 없음이 운영 반영 조건이다. 점수는 해당 검사 범위의 내부 평가이며 무결점 보증은 아니다.

1000×620 지도에서 건물 중심은 알고리즘(500,135), 컴퓨팅(235,250), 데이터(765,250), AI(300,460), 디지털 문화(700,460)이다. 중앙 하나와 좌우 두 쌍으로 대칭 배치한다. 시작 위치는 (500,340), 문은 건물 중심보다 아래에 둔다. 좁은 화면에서도 지도 위치를 유지해 공간 일관성을 보존하고 바로가기 목록을 두 열로 조정한다. 이는 아래 초기 모바일 건물 재배치 제안을 대체한다.

ZEP 공식 소개 https://web-app.zep.us/en 및 공식 안내 https://docs.zep.us/ 를 2026-09-13 확인했다. 참고 원리는 위에서 내려다보는 공간, 작은 아바타, 위치와 이동을 통한 목적지 선택이다. 색·건물·캐릭터는 자체 SVG로 제작한다. 실시간 통신 등 ZEP의 전체 기능을 구현한다고 표현하지 않는다.

## 1. 이번 발표에서 보여줄 경험

첫 화면을 차분한 2D 놀이터 지도로 바꾼다. 학생이 작은 캐릭터를 방향키로 움직여 다섯 수업 공간을 탐색하고, 공간 앞에서 Enter 또는 ‘들어가기’를 눌러 수업을 선택한다. 지도 위 공간을 클릭하거나 지도 아래 수업 목록을 선택해도 바로 같은 내용을 연다.

핵심 메시지는 ‘수업에 들어가고, 직접 만들고, 나의 기록으로 남긴다’이다. 캐릭터 이동은 입장 경험이며 학습 참여·과정점수의 근거로 수집하지 않는다. 필수 입장 영상이나 별도 시작 버튼으로 수업을 가로막지 않는다.

이번 범위는 한 사용자가 탐색하는 지도이다. 실시간 다중 접속 아바타·채팅·꾸미기·보상·새 평가 기능은 후속 범위로 둔다. ZEP 공식 화면과 안내의 공간 탐색 원리를 참고했으며, 외형·자산을 복제하거나 ZEP 서비스와 연동하지 않는다.

## 2. 첫 화면과 조작

- 기존 상단의 브랜드·수업·역할별 클래스룸·로그인 메뉴를 유지한다.
- 큰 소개 카드와 세 개 단원 카드 영역을 ‘정보 놀이터’ 제목, 짧은 안내, 지도, 수업 목록으로 재구성한다.
- 지도는 흰색·옅은 회청색 바탕에 낮은 건물과 연결된 길로 표현한다. 각 공간은 간결한 선과 부드러운 면으로 구분하고 제목을 항상 읽을 수 있게 한다. 과한 게임 HUD·반짝임·배경음은 넣지 않는다.
- 캐릭터는 작은 독자적인 SVG 로봇으로 만들고, 방향 전환과 걷기 정도만 표현한다. 기존 순서도 기호를 사용할 경우 엔트리 색상을 지킨다.
- 첫 방문: 지도와 공간이 약 0.6초 동안 나타나고 캐릭터가 중앙에 자리한다. 안내는 ‘방향키로 움직이거나, 가고 싶은 수업을 눌러 보세요.’로 쓴다. 입장 연출 중에도 클릭 가능하다.
- 지도에 포커스가 있을 때만 방향키를 받는다. 캐릭터가 공간에 가까워지면 이름과 ‘Enter로 들어가기’를 표시한다. 닿자마자 화면을 바꾸지 않는다.
- 공간을 클릭하면 걷기를 기다리지 않고 해당 영역의 수업 선택 패널을 연다. Tab과 Enter로도 동일하게 이용한다. Esc로 패널을 닫고 기존 위치로 돌아온다.
- 모바일은 공간 탭과 아래 수업 목록을 기본 경로로 삼는다. 가상 방향키는 이번 필수 범위에서 제외한다.
- ‘움직임 줄이기’를 제공하고 운영체제의 reduced-motion 설정을 기본값에 반영한다. 자동 등장·걷기 흔들림을 끄고 직접 선택 경로는 항상 제공한다.
- 돌아왔을 때 지도 위치·선택을 창 단위 sessionStorage에 보존한다. 첫 등장 연출을 매번 반복하지 않는다. 로그인·개인 기록 없이도 지도 탐색이 가능하다.

배치 초안:

```text
정보 놀이터                 수업 / 내 클래스룸                 로그인

정보 놀이터                 가고 싶은 수업으로 한 걸음!

    컴퓨팅 시스템                 데이터

                       작은 로봇
    디지털 문화                   알고리즘과 프로그래밍

                       인공지능

방향키로 이동 · Enter로 입장             움직임 줄이기
수업 바로 고르기: 다섯 영역의 접근 가능한 목록
```

지도 크기는 화면 폭과 높이에 반응한다. 좁은 화면에서는 대칭 지도 위치를 유지하고 아래의 큰 바로가기 목록을 두 열로 배치한다. 로그인 메뉴·수업 목록이 화면 밖으로 밀리지 않게 한다.

## 3. 전체 교육과정 구성

로컬 교과서 PDF의 목차(PDF 6~7페이지)를 참고했다. 아래 공간 이름은 제안이며 화면에서 정식 영역 이름을 함께 표시한다. 특정 출판사와 단원 번호는 제품에 고정하지 않는다.

| 지도 공간 | 정식 영역 | 담을 세부 주제 | 이번 제공 범위 |
|---|---|---|---|
| 컴퓨터 공작소 | 컴퓨팅 시스템 | 컴퓨팅 시스템, 운영체제, 피지컬 컴퓨팅 시스템과 구현 | 주제별 소개·핵심 질문 |
| 데이터 탐험실 | 데이터 | 데이터 표현과 디지털 표현, 수집·관리, 구조화, 분석 | 주제별 소개·핵심 질문 |
| 알고리즘 연구소 | 알고리즘과 프로그래밍 | 문제 이해·분석, 핵심 요소 찾기, 알고리즘·분석, 프로그래밍, 논리 연산·제어 구조, 함수·오류 찾기와 수정, 소프트웨어 문제 해결 | 기존 세 활동 연결 + 나머지 주제 소개 |
| AI 실험실 | 인공지능 | 개념·특성, 학습, 인공지능을 통한 문제 해결, 윤리 | 주제별 소개·핵심 질문 |
| 디지털 시민 광장 | 디지털 문화 | 디지털 사회와 직업, 디지털 윤리, 개인정보, 저작권 | 주제별 소개·핵심 질문 |

영역에 들어가면 설명 한 문장, 생각해 볼 질문, 세부 주제 목록을 표시한다. 새 설명과 질문은 직접 작성하며 교과서 본문·그림·문항을 옮겨 싣지 않는다. 예: 데이터 영역의 질문은 ‘같은 자료도 정리하는 방법에 따라 다른 사실이 보일까?’이다.

알고리즘 영역에서 문제 추상화·알고리즘 설계·순서도 연구소는 ‘활동 시작’으로 기존 개념·퀴즈·실습에 연결한다. 그 외 주제도 소개를 열어 읽을 수 있으며 ‘실습 준비 중’을 명확히 표시한다. 읽은 것만으로 제출 기록이나 완료 점수를 만들지 않는다. 다른 네 영역을 단순한 비활성 회색 카드로 만들지 않는다.

소개 공개는 해당 영역의 실습까지 구현됐다는 의미가 아니다. 발표에서도 ‘전체 교육과정을 담는 구조, 알고리즘 영역에서 작동하는 학습·기록·평가’로 설명한다.

## 4. 구현 경계와 순서

1. **배포 제외부터 확보**: schoolbooks/를 .gitignore와 .vercelignore에 명시한다. 구현 전 Git은 *.pdf를 제외했으나 Vercel 제외 파일에 교과서 폴더가 명시되어 있지 않아 두 파일에 폴더 제외를 추가했다. 원본·추출 텍스트·렌더 이미지가 커밋과 배포 목록에 없는지 확인한다. PDF와 파생 자료를 외부 AI·이미지 생성 서비스에 보내지 않는다.
2. **교육과정 데이터와 소개 화면**: js/data/curriculum.js에 영역·주제·설명·질문·활동 연결·이용 가능 상태를 관리한다. 기존 UNIT_META와 표시 이름을 중복 유지하지 않도록 연결한다. 기존 unit1/unit2/unit3 경로와 기록 키는 보존한다.
3. **정적인 지도와 바로가기**: index.html 홈에 지도와 접근 가능한 수업 목록, 영역 선택 패널을 연결한다. 이 단계부터 발표 가능한 모든 진입 경로가 작동해야 한다.
4. **캐릭터 이동과 짧은 연출**: js/core/playground.js와 css/playground.css에서 구현한다. SVG·HTML·CSS와 requestAnimationFrame으로 만들고 별도 게임 엔진·영상·프레임워크를 도입하지 않는다. 복잡한 미로나 길찾기 없이 열린 보행 영역과 다섯 진입 구역으로 구성한다.
5. **핵심 검증 후 전달**: 변경 파일과 PRD를 동기화하고 검토 가능한 커밋을 만든다. 운영 병합·배포는 사용자가 이번 작업에 명시적으로 승인했다. 독립 검토 기준을 통과한 변경만 해커톤 운영 브랜치에 반영한다.

기존 화면 전환 함수를 통해 입장하여 수행평가 중 이동 제한과 교사 작업 중 잠금을 우회하지 않는다. 다른 화면 진입·브라우저 포커스 해제·탭 숨김 시 키 상태를 초기화하고 이동 루프를 정지한다. 입력창에서 방향키를 가로채지 않는다. 평가·로그인·기록 저장·Firebase 구조와 권한은 변경하지 않는다.

캐릭터와 건물은 코드 기반 SVG로 먼저 제작한다. 이번 작은 지도에는 이미지·영상 생성이나 추가 에이전트 호출이 필수적이지 않다. 별도 일러스트가 필요해질 경우 승인된 시각 방향을 기준으로 독자적인 자산만 생성한다.

## 5. 발표 전 우선순위

- **필수**: 다섯 영역과 세부 주제, 실제/준비 중 상태, 클릭 입장, 캐릭터 방향키 이동, 기존 세 활동 연결, 소개 화면, 모바일 목록, 교과서 배포 제외.
- **필수 범위가 안정되면**: 등장 연출·걷기 모션·공간 근접 강조·위치 복귀. 이동 자체가 불안정하면 정적 지도와 클릭 경로로 즉시 축소할 수 있게 분리한다.
- **발표 이후**: 서비스 전체 클릭·모달·페이지 이동의 부드러운 전환, 신규 영역의 퀴즈·실습·기록, 다중 접속 여부 검토. 지도 구현을 전체 모션 개편으로 확대하지 않는다.

## 6. 시간을 아끼는 검증 기준

사용자의 2026-09-13 요청에 따라 코드로 확인 가능한 사항은 코드 검토와 필요한 자동 검사로 확인한다. 계획 작성에는 브라우저 캡처를 사용하지 않았고, 구현 후에는 지도 배치와 좁은 화면의 가독성을 위해 필요한 대표 화면만 확인한다.

- 코드: 주제 누락·중복, 연결 경로, 상태 표시, 평가 잠금, 키 입력 범위, 루프 정리, sessionStorage 사용, 배포 제외를 확인한다.
- 실제 화면: 데스크톱에서 이동→근접→입장→기존 활동→홈 복귀를 한 번 확인한다. 창을 좁혔다 늘려 지도·목록·메뉴 접근성을 확인하고 대표 좁은 화면 한 번만 남긴다. 반복 전체 페이지 캡처는 하지 않는다.
- reduced-motion, 키보드 탐색, 지도 밖 화살표 스크롤, 포커스 잃은 후 멈춤을 확인한다. 이 조작 검증은 스크린샷이 필수인 검사가 아니다.
- 변경하지 않은 로그인·기록·평가 전체 실서버 시나리오를 재실행하지 않는다. 연결 코드 변경이나 오류가 있으면 관련 검사만 추가한다.

## 7. 약 1분 발표 동선

1. ‘정보 시간의 모든 주제로 들어가는 놀이터입니다.’ — 캐릭터를 알고리즘 연구소로 이동한다.
2. ‘현재 알고리즘 영역은 직접 해 볼 수 있습니다.’ — 기존 실습에 들어가 짧게 조작한다.
3. ‘학생이 만든 내용은 제출 시점의 기록으로 남습니다.’ — 내 기록 저장과 실제 기록을 보여준다.
4. ‘교사는 반별로 이 기록과 수행평가 제출을 확인합니다.’ — 준비된 교사 화면으로 마무리한다.

이동 장면은 5~10초 정도로 짧게 사용한다. 발표의 중심은 공간 연출에서 실제 학습·기록·교사 확인으로 이어지는 흐름이다.
