# 정보 놀이터 — 현재 인수인계

이 문서는 새 PC나 새 AI가 가장 먼저 읽는 현재 상태 요약이다. 이전 대화를 알고 있다고 가정하지 않는다. 작업 규칙은 `AGENTS.md`, 교육 의도는 `INTENT.md`, 기능의 상세 최신 명세는 `PRD.md`가 최상위 기준이다.

- 갱신 날짜: 2026-09-13
- 운영 저장소: https://github.com/DonghyunT/donghyun-hackthon
- 운영 브랜치: `feature/hackathon`
- 운영 주소: https://donghyun-hackthon.vercel.app/

## 1. 새 PC·새 AI가 먼저 확인할 것

문서에 적힌 커밋 해시보다 원격 Git 상태가 우선한다. 다음 순서로 현재 사실을 복원한다.

1. `git status --short --branch`로 미커밋·미추적 파일과 현재 브랜치를 확인한다.
2. `git fetch origin --prune` 후 `origin/feature/hackathon`의 최근 커밋을 확인한다.
3. `AGENTS.md` → `INTENT.md` → 이 문서 → `PRD.md`의 최신 관련 절 순서로 읽는다.
4. 진행 중 작업이 이 문서에 명시돼 있고 원격 작업 브랜치가 존재할 때만 그 브랜치를 이어받는다. 그 외 새 작업은 최신 `origin/feature/hackathon`에서 별도 브랜치를 만든다.
5. 문서의 계획, 코드의 구현, 검사 결과, 원격 푸시, 운영 배포를 서로 다른 상태로 취급한다.

한 PC의 미커밋 파일과 대화 내용은 다른 PC나 AI가 볼 수 없다. 이어갈 작업은 반드시 안전한 단위로 커밋하고 원격 작업 브랜치에 푸시한 뒤 이 문서에 브랜치·커밋·남은 일을 기록한다.

## 2. 현재 기준 상태

- 현재 진행 중인 제품 코드 작업: 없음.
- 현재 문서 작업: 완료. `codex/context-portability`에서 새 PC·새 AI의 문맥 복원 절차를 정비하고, 사용자 승인에 따라 이 파일을 `HACKATHON_HANDOFF.md`에서 `HANDOFF.md`로 바꾸어 모든 현재 참조를 갱신했다. `AGENTS.md`에는 Git 중심 복원·한 작업 한 AI·위험 기반 검증·현재 운영 브랜치 원칙을 최소 범위로 반영했다. 운영 병합 커밋은 `4d3fd6c`이며 Vercel 홈의 새 배포 시각과 HTTP 200을 확인했다. Markdown 문서는 Vercel 공개 자산으로 직접 제공되지 않으며 Git 저장소에서 읽는다.
- 최신 기준은 항상 `origin/feature/hackathon`이다. 이 문서를 읽는 시점에 원격 로그를 다시 확인한다.
- 최근 대문 제품 병합 커밋: `a5e8fd6`.
- 최근 상태 문서 커밋: `71f4b7a` 이후의 `origin/feature/hackathon` 로그를 기준으로 한다.
- 2026-09-13 Vercel 운영 화면에서 HTTP 200, 정문 로봇 표시·방향키 이동·첫 안내 제거, AI 튜터 닫힘·열림, 콘솔 오류 0건을 확인했다.
- 로컬에서 `index.html`을 `file://`로 직접 열면 외부 SVG 마스크 처리 차이로 로봇이 보이지 않을 수 있다. 개발 확인은 `node tools/preview.cjs`의 `http://127.0.0.1:4173/?demo=1`을 사용한다. 실제 로그인·저장·AI는 운영 환경에서 별도로 검증한다.

## 3. 현재 운영 기능

- 학생용 이름은 **정보 놀이터**이며 첫 화면은 넓은 픽셀아트 캠퍼스다.
- 로봇은 하단 정문에서 출발한다. 키보드 방향키 또는 모바일 방향 버튼으로 이동하며, 건물 클릭이나 가까이에서 Enter로 수업 페이지에 들어간다.
- 다섯 교육과정 영역과 25개 주제를 안내한다. 실제 퀴즈·실습이 연결된 영역은 문제 추상화, 알고리즘 설계, 순서도 연구소 세 가지다. 나머지 영역의 활동까지 구현됐다고 표현하지 않는다.
- 학생 308명은 2학년 1~11반, 각 1~28번이며 개인 비밀번호로 로그인한다. 교사는 Google 로그인 또는 비상계정을 사용한다.
- 게스트 학생·교사는 발표용 2-12반의 실제 Firebase 기능을 사용한다. 게스트 교사는 실제 1~11반 자료에 접근할 수 없다.
- 세 활동의 퀴즈·실습 기록, 학생 기록 조회, 교사의 학급별 기록·수행평가 관리가 연결돼 있다.
- 공유 PC 보호를 위해 인증 지속성과 브라우저 임시 상태는 SESSION·`sessionStorage` 원칙을 따른다. 서버 자료의 보관·삭제 정책은 별도 확정 전까지 완료로 표현하지 않는다.

세부 근거는 [문서 안내](INDEX.md)에서 필요한 보고서만 선택한다. 과거 보고서의 브랜치·배포 상태를 현재 지시로 사용하지 않는다.

## 4. 고정된 제품·교육 합의

- 일반 실습은 학생이 AI 도움과 재시도를 활용해 완성 경험을 얻도록 한다. 수행평가는 PRD에 정한 별도 도움·제출 원칙을 따른다.
- 학생에게 추가 설명문이나 성찰 작성을 임의로 요구하지 않고, 교사의 채점 부담을 불필요하게 늘리지 않는다.
- 학기 수행평가 3회의 30·30·40점 기획과 한 번의 순서도 평가 내부 30·30·40 배점을 혼동하지 않는다.
- 학생에게 수행평가 결과는 제출 여부만 표시한다. 자동 계산은 교사 최종 판단 전 참고값이다.
- 프런트엔드는 HTML/CSS/Vanilla JavaScript를 유지한다. Firebase·Vercel·AI 키·DB 구조·권한 변경은 별도 영향 확인과 승인이 필요하다.
- `백업용/`, 교과서, 학생 비밀번호, 서비스 계정, `.env`와 비공개 자료를 수정·업로드·커밋하지 않는다.

## 5. AI와 PC를 교체하는 규칙

- 한 작업은 한 AI가 계획부터 구현·검토·검증까지 연속해서 맡는다. 서로 다른 AI에게 같은 작업을 조각내 실시간으로 주고받게 하지 않는다.
- Codex 사용이 어렵다면 다른 AI 하나가 최신 Git과 이 문서를 읽고 남은 작업 전체를 이어받는다. 이전 AI의 대화가 아니라 커밋된 코드와 문서를 기준으로 판단한다.
- AI를 바꾸기 전에는 기존 AI의 작업을 멈추고 브랜치명, 마지막 커밋, 미완료 항목, 검사 결과를 남긴다. 새 AI는 같은 파일을 동시에 수정하지 않는다.
- 같은 작업 브랜치를 여러 PC에서 동시에 편집하지 않는다. PC를 옮길 때는 먼저 현재 PC에서 커밋·푸시하고, 새 PC에서 fetch 후 해당 원격 브랜치를 선택한다.
- 원격에 없는 로컬 변경이 있다면 새 AI가 추측해 재작성하지 않는다. 원래 PC에서 복구하거나 사용자에게 범위를 확인한다.

## 6. 남아 있는 한계

- 대규모 동시 접속, 동시 게스트 편집, 실제 Google 팝업 로그인, 실제 성적 확정 운영은 별도 확인이 필요하다.
- 다음 차시 이어하기 방식과 서버 자료 보관·삭제 기간은 미확정이다.
- `file://` 직접 실행은 전체 기능 지원 환경이 아니다.
- 서비스 전체의 부드러운 화면 전환은 낮은 우선순위의 [UX 후속 작업](UX_BACKLOG.md)이다.

## 7. 다음 작업을 끝낼 때 갱신할 내용

다음 AI는 작업 종료 또는 중단 전에 이 문서의 2절을 현재 상태로 바꾸고, 새 요구사항은 PRD의 관련 절에 계획·구현·검증 상태를 나눠 기록한다. 다음 항목을 빠뜨리지 않는다.

- 작업 브랜치와 마지막 커밋
- 원격 푸시 여부
- 변경 파일과 보호한 범위
- 실행한 검사와 실제 화면 확인
- 미확인 사항과 다음 한 가지 행동
- 운영 병합·Vercel 배포·Firebase 변경 여부
- 미커밋·미추적 파일

새 세션에 전달할 문구는 [세션 시작·종료 프롬프트](START_NEXT_SESSION.md)를 사용한다.
