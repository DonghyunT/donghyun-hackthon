# 대문 화면 맞춤과 AI 튜터 탭 — Gemini 구현 명세

> 상태: Gemini 구현 후 Codex 로컬 검토·보완 완료, 운영 전 · 2026-09-13
> 기준: `feature/hackathon` 커밋 `f4e8c8b`  
> Gemini 구현 브랜치: `codex/gemini-home-viewport-tutor`

## 1. 목표와 완료 모습

첫 진입에서 사용자가 스크롤하지 않아도 **픽셀 지도, 출발 로봇, 이동 안내, 필수 조작부까지 한 화면에** 보여야 한다. PC·디벗·태블릿·모바일 모두 로봇을 직접 움직여 건물에 들어가는 화면임을 바로 이해할 수 있어야 한다. 지도 전체를 새로 그리거나 잘라 확대하지 않고 현재 16:9 픽셀 맵과 다섯 건물 좌표를 유지한다.

대문 위의 중복 소개 문구는 제거한다. 전역 헤더에 이미 `정보 놀이터` 이름이 있으므로 화면에는 별도의 큰 제목·홍보 문장을 두지 않고 접근성용 제목만 남긴다. 지도 안에는 첫 이동 전까지만 짧은 행동 안내를 표시한다.

AI 튜터는 데스크톱에서 우측 벽에 아이콘 폭만 남기고 접혀 있다가 마우스 호버 또는 키보드 초점을 받으면 전체 이름이 드러난다. 터치 환경에는 호버가 없으므로 아이콘 버튼 전체를 항상 표시하고 한 번 탭하면 바로 채팅을 연다.

## 2. 대문 레이아웃과 조작

### 화면 높이 우선 맞춤

- 현재 뒤쪽의 `#view-roadmap.playground-home { width:94vw }`, `.pg-map { aspect-ratio:16/9 }`가 앞선 높이 제한을 덮는 문제를 정리한다. 같은 선택자의 중복 규칙을 하나의 최종 규칙군으로 합친다.
- `--app-header-height`는 `navigation.js`의 기존 `ResizeObserver` 측정값을 그대로 사용한다. 대문은 남은 `100dvh - var(--app-header-height)` 안에서 상하 여백, 지도, 상태·입장 도구 모음을 배치한다.
- 761px 이상에서는 지도 폭을 화면 폭뿐 아니라 남은 높이로 제한한다. 최종 폭은 `94vw`, `1680px`, `가용 지도 높이 × 16/9` 중 가장 작은 값이 되게 한다. 1366px 폭에서 헤더가 두 줄이 되어도 실제 측정 높이를 반영한다.
- 760px 이하에서도 지도 전체 16:9 비율을 유지한다. 지도·모바일 방향 패드·상태 안내가 첫 화면에 들어오도록 대문 상하 여백과 도구 모음 간격을 줄인다. 수업 바로가기와 푸터까지 첫 화면에 넣을 필요는 없지만 `.pg-map-shell` 전체는 잘리면 안 된다.
- 창 높이가 매우 낮아 한 화면 배치가 불가능한 경우 지도를 읽기 어려운 크기까지 축소하지 않는다. 최소 지도 폭을 유지하고 정상적인 세로 스크롤을 허용한다. 페이지 가로 넘침은 허용하지 않는다.

### 문구와 첫 행동 유도

- `index.html`의 보이는 `.pg-heading` 소개 영역은 제거하고 `정보 놀이터 수업 지도`를 스크린 리더용 제목으로 남긴다.
- 기존 장식 문구 `오늘은 어떤 발견을 해 볼까?`는 제거한다.
- 지도 안 첫 안내는 `로봇을 움직여 수업 건물로 가 보세요`로 통일한다. 키보드 환경에는 `방향키`, 터치 환경에는 `화면의 방향 버튼`을 조작 힌트로 함께 보여 준다.
- 첫 유효 이동이 시작되면 안내를 숨긴다. 같은 탭에서 지도에 돌아왔을 때 반복하지 않도록 새 상태를 `sessionStorage`에 저장한다. 서버나 학습 기록에는 저장하지 않는다.
- 첫 이동 전 로봇 주변에 정적인 방향 표시 또는 약한 주목 효과를 준다. `prefers-reduced-motion: reduce`에서는 애니메이션 없이 윤곽만 표시한다.
- 기존 상태 문구는 유지한다. 건물 근처에서는 건물 이름과 `Enter로 들어가기`, 그 외에는 이동·클릭 입장 안내를 표시한다.

### 모바일·터치 이동

- 760px 이하 또는 `pointer: coarse` 환경에는 상·하·좌·우 네 버튼의 작은 방향 패드를 표시한다. 각 버튼은 최소 44×44px 클릭 영역과 `위/아래/왼쪽/오른쪽으로 이동` 접근성 이름을 가진다.
- 버튼을 누르고 있는 동안 기존 이동 루프와 충돌 판정을 사용해 연속 이동하고, `pointerup`, `pointercancel`, 포인터 캡처 상실, 창 포커스 해제, 화면 이탈 시 즉시 멈춘다. 짧게 탭해도 눈에 보이는 최소 한 단계는 움직인다.
- 방향 패드는 별도 이동 엔진을 만들지 않는다. 키보드와 터치 입력이 같은 좌표·속도·충돌·방향 전환·걷기 상태를 사용하도록 입력 시작/종료 함수를 공통화한다.
- 기존 건물 클릭, Tab 선택, Enter 입장, 아래 수업 바로가기는 유지한다. 모바일에서도 건물을 탭해 바로 들어갈 수 있다.
- 수행평가 이동 잠금과 교사 상태 저장 중 잠금은 방향 패드에도 똑같이 적용한다.

## 3. AI 튜터 접힘 동작

- `studio-ui.css`의 `#tutor-fab-btn { transform:none }` 덮어쓰기를 제거하고 최종 스타일을 공통 UI 파일 한곳에서 관리한다. 이전 `flowchart.css` 규칙과 상충하지 않게 정리한다.
- 호버 가능한 환경에서 닫힌 버튼은 우측 화면 밖으로 이동하되 44px 아이콘 손잡이는 항상 보인다. `:hover`, `:focus-visible`, `.chat-open`일 때 전체 `AI 튜터` 또는 `닫기`가 보이도록 `translateX(0)`으로 전환한다.
- 접힌 상태에서도 버튼 클릭은 바로 채팅을 연다. 호버로 펼친 뒤 다시 클릭해야 하는 2단계 조작을 만들지 않는다.
- `aria-controls="tutor-chat-window"`, `aria-expanded`, 동작에 맞는 `aria-label`을 갱신한다. 보이는 문구만 바꾸기 위해 버튼 전체 `innerHTML`을 반복 교체하지 말고 아이콘과 라벨 노드를 유지해 상태만 변경한다.
- `hover:none` 또는 680px 이하에서는 밀어 숨기지 않는다. 44px 이상의 아이콘 버튼을 우측에 온전히 표시하고 시각 문구는 생략할 수 있으나 접근성 이름은 유지한다.
- `prefers-reduced-motion: reduce`에서는 슬라이드 애니메이션 없이 즉시 상태를 바꾼다. 수행평가 중 튜터를 숨기는 기존 규칙은 유지한다.
- 채팅 창은 `min(380px, calc(100vw - 24px))` 범위와 현재 동적 화면 높이 제한 안에 두어 모바일에서 잘리지 않게 한다. 대문의 방향 패드나 주요 입장 버튼을 가린 상태가 되지 않도록 닫힌 위치를 확인한다.

## 4. 수정 범위와 보호 범위

주요 수정 대상은 `index.html`, `css/playground.css`, `css/studio-ui.css`, `js/core/playground.js`, `js/core/ai-tutor.js`, `tests/playground.test.cjs`이다. AI 튜터 상태 검사가 기존 테스트로 불가능하면 작은 DOM 단위 테스트를 하나 추가한다. 새 이미지·프레임워크·게임 엔진·외부 라이브러리를 추가하지 않는다.

다섯 건물 이미지·좌표·충돌 구역·수업 페이지와 세 기존 활동 경로, 캐릭터 위치 복구 키 `playground-position-v2`, 로그인·학습 기록·평가·Firebase·AI API 프롬프트는 변경하지 않는다. `AGENTS.md`, `schoolbooks/`, 비밀번호와 비밀 설정을 수정하거나 커밋하지 않는다. 최근 `f4e8c8b`의 샌드위치 완료 모달·복사 버튼 수정도 보존한다.

## 5. 검사와 인수 조건

### 자동 검사

- `node tools/check.cjs`
- `node --test tests/playground.test.cjs`와 새로 추가한 관련 테스트
- 기존 전체 Node 검사를 실행하고 이번 변경과 무관한 실패가 있으면 구분해 기록한다.
- 방향 버튼 누름·해제·취소, 첫 이동 안내 1회 처리, 잠금 중 이동 거부, 화면 이탈 시 정지를 단위 검사한다.
- AI 튜터의 닫힘/열림 `aria-expanded`, 라벨·아이콘 상태와 수행평가 숨김 규칙을 확인한다.

### 실제 화면

로컬 서버 환경에서 최소 `1920×900`, `1366×650`, `1024×768`, `768×1024`, `390×844`, `360×740` 뷰포트를 확인한다.

- 첫 진입 시 `.pg-map-shell`의 위·아래가 뷰포트 안에 있고 출발 로봇과 조작 안내가 보인다.
- 폭과 높이를 줄였다 늘려도 지도 왜곡, 건물·라벨·로봇 좌표 어긋남, 페이지 가로 넘침이 없다.
- PC 방향키와 터치 방향 패드로 다섯 건물 앞에 갈 수 있고, Enter·입장 버튼·건물 클릭이 기존 수업 페이지를 연다.
- 데스크톱 AI 튜터는 닫힘 시 44px 손잡이만 보이고 호버·키보드 초점에서 펼쳐지며 클릭 한 번으로 열린다. 모바일에서는 아이콘 버튼이 잘리지 않는다.
- 채팅 열기·닫기, 지도 복귀, 수행평가·교사 잠금, `prefers-reduced-motion`에서 콘솔 오류가 없다.

완료 보고에는 브랜치와 커밋, 변경 파일, 자동 검사 결과, 확인한 실제 뷰포트와 미확인 환경을 남긴다. `feature/hackathon` 병합·푸시와 운영 배포는 사용자 승인 전 수행하지 않는다.

## 6. 구현·검토 결과

Gemini 초안 `a582573`은 대문 문구 제거와 튜터 상태 변경의 기본 방향을 반영했지만 `css/playground.css`의 기존 핵심 규칙 대부분을 삭제해 지도 구성과 수업 페이지가 무너졌고, 방향 패드가 기존 지도 포커스 조건 때문에 안정적으로 움직이지 않았다. 신규 검사와 PRD·인수인계 갱신도 없었다.

Codex는 `codex/review-home-viewport-tutor`에서 기존 픽셀 지도·건물·캐릭터·수업 페이지 스타일을 복원하고, 실제 헤더·도구 모음 높이로 데스크톱 지도 폭을 계산하도록 보완했다. 모바일 방향 패드는 키보드와 좌표·충돌 엔진을 공유하며 포인터 해제·취소와 잠금 상태에서 정지한다. 첫 이동 안내는 정적 DOM과 `sessionStorage`로 처리하고, 튜터 버튼은 초기·열림·닫힘 접근성 상태를 유지한다.

검증은 문법·자산 검사, 관련 16개와 전체 61개 Node 검사, 로컬 Chrome의 여섯 뷰포트 화면 맞춤과 가로 넘침, 방향키·모바일 방향 버튼, 수업 페이지, 튜터 열기·닫기를 포함한다. 운영 환경과 실제 모바일 기기는 아직 확인하지 않았다.
