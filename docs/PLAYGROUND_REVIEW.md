## 독립 검사

`node tests/playground.test.cjs`: **9개 통과, 실패 0개**. 실제 `curriculum.js`와 `playground.js`를 VM/최소 DOM에서 실행해 다음 동작을 검사했다. 브라우저 또는 실제 Firebase 검증으로 표현하지 않는다.

1. 5개 고유 영역·25개 주제·3개 기존 활동 경로와 영역 패널 내용.
2. 중앙 광장에서 5개 건물 문까지 방향키 이동 후 Enter 입장.
3. 건물 충돌·지도 경계와 키 해제 후 잔여 프레임 없음.
4. blur, 지도 숨김, 평가 잠금, leave 후 키와 프레임 정리.
5. 입력창 키 비간섭, 평가 및 교사 작업 중 입장 차단.
6. 새 컨트롤러에서 위치 복구, 잘못된 JSON·좌표·건물 내부 좌표의 안전한 초기화.
7. 움직임 줄이기에서 이동·직접 입장은 유지하고 걷기 애니메이션은 제거.
8. OS 움직임 줄이기의 명시적 상태와 OS 설정 해제 시 저장된 개인 선택 복귀.
9. 짧은 첫 등장 후 클래스 제거 및 같은 세션 재실행 시 등장 반복 없음.

처음 7개는 `node --test tests/playground.test.cjs`로 통과했다. 추가 2개 이후 동일 명령의 격리 자식 프로세스가 로컬 sandbox에서 EPERM으로 제한되어, `node tests/playground.test.cjs`로 9개를 모두 실행·통과했다. 제품 오류와 구분한다.

## 피드백과 수정 확인

- 첫 등장 클래스가 남아 홈 복귀 때 다시 애니메이션을 실행할 가능성을 지적했다. 650ms 후 제거하도록 수정했고 독립 검사에서 확인했다.
- OS 움직임 줄이기가 CSS에서 계속 적용되는 반면 버튼이 꺼짐으로 표시될 수 있음을 함께 검토했다. OS 설정 우선 및 `기기 설정: 움직임 줄이기` 비활성 버튼으로 상태를 일치시켰다.
- 버튼 본체 밖의 건물 간판도 클릭할 수 있도록 label의 pointer-events를 활성화했다. 부모 버튼의 클릭 이벤트로 영역 입장이 이어진다.
- 모바일 건물 자체를 2열로 재배치한다는 초기 계획을 실제 구현인 대칭 지도 유지·2열 바로가기로 갱신했다.
- 계획·PRD의 구현 상태와 이번 병합·배포 승인을 최신 상태로 갱신했다.

주 작업자의 최종 실제 브라우저 확인: 데이터 건물의 간판 `strong`을 직접 클릭해 데이터 패널이 열렸다. 390×844 화면의 알고리즘 dialog는 x16/y59, 약 343×726이며 가로 넘침이 없었다. 닫기 버튼(55×38)과 세 활동 행(각 289×88)은 잘리지 않았고, 아래 주제는 패널 안에서 스크롤해 읽을 수 있었다. 이 결과는 주 작업자가 수행해 전달한 근거로 구분한다.
