# 새 세션 시작용 공통 프롬프트

저장소 파일을 읽을 수 있는 AI에 전달한다. 특정 모델·IDE에 의존하지 않는다. 마지막 줄의 작업을 바꿔 사용한다.

```text
이 저장소의 작업을 이어가자. 이전 대화를 알고 있다고 가정하지 마.

먼저 Git 상태, 현재 브랜치와 최근 커밋을 확인해줘.
AGENTS.md → INTENT.md → docs/HACKATHON_HANDOFF.md 순서로 읽고,
PRD.md 최신 관련 절과 이번 요청에 필요한 코드·상세 문서만 확인해줘.
계획·실제 구현·검증·배포 상태를 구분하고 오래된 지시서를 다시 실행하지 마.
문서와 코드가 다르면 차이를 짧게 알려줘.

기존 서비스와 학생 자료를 보호하고 미반영 변경을 덮어쓰지 마.
새 변경은 별도 브랜치에서 작업하고 이번 변경의 병합·배포는 내 승인 후 진행해줘.
교과서 PDF와 비밀 자료를 업로드하거나 대화에 노출하지 마.
브라우저 캡처는 필요한 부분만 사용하고 관련 검사 위주로 검증해줘.

시작 전에 현재 상태·이번 범위·불확실한 부분을 짧게 요약하고 진행해줘.
종료·중단 때 PRD의 관련 상태와 HACKATHON_HANDOFF.md를 갱신하고,
브랜치·커밋·미반영 파일·검증 결과·다음 작업·푸시/병합/배포 여부를 알려줘.

이번에 할 일: [원하는 작업]
```

파일 접근이 불가능한 채팅형 AI에는 필요한 문서 내용만 제공하고 기획·검토에 사용한다. 실제 코드를 읽지 못한 답변을 코드 검증으로 간주하지 않는다. 교과서나 비밀 파일을 대체 첨부하지 않는다.

## Codex → Gemini 릴레이

한 기능을 두 AI가 함께 맡을 때는 같은 브랜치에서 동시에 편집하지 않고 아래 순서대로 전달한다.

### 1. Codex에 설계 요청

```text
이번 작업은 [원하는 기능]이야.
아직 구현하지 말고 Gemini가 바로 코딩할 수 있도록 작업 명세를 작성해줘.
현재 저장소를 확인하고 작업 브랜치 이름, 수정 범위, 건드리지 않을 부분,
완료 조건, 검사 방법, PRD와 인수인계 갱신 위치까지 정해줘.
```

### 2. Gemini에 구현 요청

```text
이 저장소의 AGENTS.md, INTENT.md, PRD.md, docs/HACKATHON_HANDOFF.md와
Git 상태를 먼저 확인해줘. 아래 확정 명세만 구현해줘.

[Codex가 작성한 구현 명세]

최신 origin/feature/hackathon을 기준으로 명세에 지정된 새 작업 브랜치를 만들어 작업해줘.
관련 검사 후 커밋하고 원격에 푸시한 다음 브랜치명, 커밋 해시, 변경 파일,
검사 결과와 미확인 사항을 알려줘. 병합·배포는 하지 말고 편집을 멈춰줘.
AGENTS.md와 비밀 자료는 수정하거나 커밋하지 마.
```

### 3. Codex에 검토·보완 요청

```text
Gemini 작업이 끝났어.
브랜치: [브랜치명]
커밋: [커밋 해시]

원격 변경을 확인하고 요구사항 누락, 회귀 위험, UI/UX, 보안·데이터 보호,
실제 사용 흐름을 검토해줘. 필요한 수정은 Gemini 커밋에서 분기한 별도
codex/review-<작업명> 브랜치에서 보완하고 검사해줘.
아직 feature/hackathon 병합이나 배포는 하지 마.
```

### 4. 승인 후 운영 반영 요청

```text
검토 결과대로 feature/hackathon에 병합하고 배포까지 진행해줘.
운영 커밋과 배포 상태를 확인하고 PRD와 인수인계 문서를 갱신해줘.
```

병합만 승인할 때는 마지막 지시를 `배포하지 말고 병합까지만 진행해줘`로 바꾼다. 다만 `feature/hackathon` 푸시가 Vercel 자동 배포를 시작할 수 있으므로 실행 전에 연결 상태를 확인한다.

## 세션 종료용 문구

```text
다음 AI에게 넘길 수 있게 docs/HACKATHON_HANDOFF.md를 갱신해줘.
새로 합의한 기능은 PRD에 계획/구현/검증 상태를 구분해 반영해줘.
현재 브랜치, 커밋, 미반영 변경, 검증 근거, 다음 작업, 승인·배포 상태를 남겨줘.
비밀값은 넣지 마. Git에 아직 반영되지 않은 문서나 코드가 있으면 알려줘.
```
